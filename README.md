# ميزان · Mizan

وكيل فرز بلاغات أمنية. يقرأ البلاغ المرسل من باحث خارجي والكود المرتبط به، **يكتشف محاولات حقن التعليمات** المخفية داخل نص البلاغ، يتحقق من الادعاء بقراءة الكود فقط (بلا تشغيل أي شيء)، ويقترح قراراً (قبول / طلب معلومات / مكرر / رفض) مع الأدلة ومسودة رد. **القرار النهائي دائماً لمهندس بشري.**

مشروع لهاكاثون Meta Global AI Developer Hackathon 2026 (مسار المطورين المستقلين، محور Build for Your World).

## حدود مقصودة ومهمة

- **لا تشغيل كود مطلقاً.** لا يُنفَّذ أي استغلال ولا يُختبر أي PoC، لا محلياً ولا على أي نظام خارجي.
- **البلاغ بيانات غير موثوقة دائماً.** يُمرَّر داخل حدود واضحة في الطلب، ولا يُدمَج أبداً في تعليمات النظام. `tests/test_all.py::test_report_is_isolated_and_not_executed_as_instructions` يثبت هذا آلياً.
- **حواجز صلبة في `triage.normalize()`:** ادعاء يناقضه الكود لا يمكن أن يصبح "قبول" تلقائياً، وناتج أداة فحص خام بلا تحليل لا يمكن أن يصبح "قبول" تلقائياً، بصرف النظر عمّا يقوله النموذج.

## التشغيل (Python 3.9+ فقط، بلا أي حزمة إضافية)

```bash
cp .env.example .env      # ثم ضع المفتاح داخل .env
python server.py
```

افتح http://localhost:8000 — وجرّب الأمثلة الجاهزة الثلاثة (تعمل بلا مفتاح):
- **محاولة حقن:** بلاغ يحاول توجيه القرار بنص مخفي.
- **بلاغ صحيح:** IDOR مدعوم فعلياً بالكود المرفق.
- **ضجيج:** ناتج أداة فحص خام بلا تحليل.

## الاختبار

```bash
python -m unittest discover -s tests -v
```
17 اختباراً، أهمها اختبار عزل البلاغ عن تعليمات النظام، واختبار أن حقن التعليمات يُكتشف ويُرفض لا يُنفَّذ.

## كيف يعمل

```
البلاغ + الكود (اختياري)
   └─ POST /api/triage ─► triage.py
         ├─ يبني رسالة Muse Spark: البلاغ داخل حدود "غير موثوق" صريحة
         ├─ Muse Spark: الادعاء، خطوات الإعادة، محاولات الحقن المكتشفة،
         │               التحقق من الكود، الخطورة، القرار المقترح، مسودة الرد
         └─ normalize(): حواجز صلبة (ادعاء متناقض أو ضجيج خام ⇒ لا قبول تلقائي)
   ◄─ النتيجة JSON ── الواجهة تعرضها كبطاقة فرز
```

| الملف | وظيفته |
|---|---|
| `server.py` | خادم HTTP (مكتبة بايثون القياسية فقط) |
| `meta_client.py` | الاتصال بـ Meta Model API |
| `prompts.py` | تعليمات النظام، مع فصل صريح للبلاغ كبيانات غير موثوقة |
| `triage.py` | تحليل الرد، والحواجز الصلبة التي لا يتجاوزها قرار النموذج |
| `demo_data.py` | ثلاث حالات جاهزة (حقن، بلاغ صحيح، ضجيج) |
| `static/index.html` | لوحة الفرز (عربي/إنجليزي) |

## ما لم يُختبر بعد (لا توجد شبكة في بيئة البناء)

1. **اسم النموذج وعنوان الـ API:** كما في مشروع "معلّم الورقة"، عدّل `META_MODEL` و`META_API_BASE` في `.env` إن ظهر خطأ اتصال.
2. **جودة كشف الحقن على حالات حقيقية:** الحالة التجريبية وضحة عمداً. جرّب بلاغات حقيقية من HackerOne/Bugcrowd العلنية لقياس الدقة الفعلية بصدق قبل التسليم.
3. **حجم الكود المُدخل:** مع مستودعات كبيرة قد تحتاج تلخيصاً أو اختيار الملفات الأوثق صلة قبل الإرسال، بدل لصق المستودع كاملاً.
